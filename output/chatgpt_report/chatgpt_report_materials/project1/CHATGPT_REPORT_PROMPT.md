# ChatGPT 보고서 작성 프롬프트

먼저 `REPORT_CONTEXT.md`와 과제 PDF 를 첨부한다. 실제 그래프까지 작성하려면 `output/chatgpt_report/chatgpt_report_materials.zip`도 첨부한다. ZIP 을 열 수 없는 환경에서는 압축을 풀어 README 의 최종 CSV/JSON 을 직접 첨부한다. 아래 본문을 복사해서 사용한다.

---

첨부한 `REPORT_CONTEXT.md`, `Project1_Assignment_0927.pdf`, 공식 Q&A 와 원시 자료를 바탕으로 **디지털전자회로 Project #1 — TCAD Device Design**의 한국어 제출 보고서를 작성해줘. 학번은 **2022142233**이다. 이름·분반은 제공하지 않았으므로 입력 칸으로 남겨줘.

먼저 과제 안내 PDF 를 읽고 목표·측정 정의·허용 설계 범위·제출 형식과 분량을 확인해줘. 보고서는 **PDF 약12 쪽, 양식 자유**이며 공식 Q&A 에서 조금 초과를 허용했다. 특정 글꼴·여백·표지 포함 규칙이 과제의 의무라고 지어내지 말고 읽기 쉬운 편집값을 선택해줘.

보고서 절 제목은 반드시 다음 이름을 사용해줘.

| 절 | 필수 내용 |
|---|---|
| Part-1-(a) | HW1 의 부족한 물리, 보완 필요성·식·구현·검증 |
| Part-1-(b) | 초기 설계→검사→재설계, 시도·지표·판단, 최종 소자 그림·8 개 spec 표 |
| Part-1-(c) | 한 knob 씩 바꾼 공식 모델 ablation 과 성능 변화 이유 |
| Part-2-(a) | 실제 1T1C 구조·연결·치수/재료, 전체 plate dQ/dV CSTORE |
| Part-2-(b) | Data0/1 ΔVBL(t)와 I(t),0.5 ns·60 mV 비교 |
| Part-2-(c) | baseline 실패→첫 합격→보존 한계 측정→여유 개선의 설계 과정 |
| Part-2-(d) | 현재 최종 셀 그림·READ/retention 표·선택 근거·검증·한계 |

두 실제 제출 파일의 checker OK 화면을 보고서에 넣어야 해. 화면이 첨부되지 않았다면 `[실제 checker OK 화면 삽입 필요]`로 표시하고 마지막 미완료 목록에도 남겨줘. 로그를 screenshot 처럼 꾸미거나 과제 예시 화면을 내 결과로 사용하면 안 돼.

컨텍스트의 전체 이력을 연구 흐름으로 재구성해줘. 모든 개발 로그를 그대로 붙이기보다 **문제→왜 바꿨는가→실제 지표→다음 판단**을 연결해줘. Part1 초기10 회 탐색과 공식 모델 재측정은 구분하고, Part2 초기 TaN 실패와 첫 #11 합격, 실제67.2 ms 측정, 후속 #19 의95.2 ms 개선을 연결해줘. 실패·중단·입력 오류·미측정도 필요한 만큼 솔직하게 설명해줘.

다음 사실은 특히 혼동하지 말아줘.

- HW1 은 이미 drift-diffusion/SRH 를 사용했다. 이번 보완은 gate 재료/기준 전위·온도에 따른 ni/SRH 매개변수·공식 μ(T) 등이다.
- 최종 Part1 수치는 공식 모델의 candidate_10/fine(0.01 V), one-knob 비교는 같은0.02 V control 을 사용한다.
- Part1/Part2 는 독립 설계다. 모든 Part2 실험에서 **Lg0.3 µm/폭0.1 µm 는 고정**했다. Gate 재료 W 는 텅스텐이며 폭 기호 W 와 별개다.
- 현재 Part2 는 후속 **#19**다. Cell retention95.198837 ms 는 finite failure bracket 의 추정이며 Data1 이 제한한다. Data0 는 **≥128 ms** 하한이지 정확한 최대값이 아니다.
- 새 #19 의64 ms Data1 마진은63.559235 mV 이고 기준60 mV 초과분이 약8.5 배 개선됐다. 마진 전체가8.5 배가 된 것은 아니다. Data0 마진 감소도 tradeoff 로 설명해줘.
- READ 는 과제가 허용한 DC-current 기반 Python 시간 루프다. Native transient PDE 를 새로 만들었다고 쓰지 말고 signed current·폭 적용 한 번·body 전하 보존을 설명해줘.
- Retention 은 worst-case BL 에서 실제 누설 적분 후 열화된 Vcell 로 재 READ 하는 판정이다. 초기 누설 상수 외삽/임의 Vcell threshold 로 대체하면 안 돼.
- 최종 bottom p+ tap·좌우 비균일 NA·S/D 비대칭 ND·source contact 위 capacitor 를 실제대로 그려줘. PDF 예시의 표면 tap 을 그대로 복제하지 말아줘.
- 루트의 이전 part2_2022142233.devsim 은 #11 이다. 현재 보고서에 대응하는 새 파일은 컨텍스트의 robust run/selected 경로다.
- 결론은 공개된 공식 조건에서의 **로컬 PASS**다. 조교 evaluator·독립 mesh·실험 정확성·공정 변동을 검증했다고 주장하지 말아줘.

CSV/JSON 을 읽을 수 있으면 실제 데이터로 번호 있는 그림·표·수식을 작성하고, 캡션에 모델·조건·단위·자료를 짧게 표시해줘. READ 시간은 ns, hold 는 ms, ΔVBL 은 mV 다. 0.5 ns/±60 mV,64 ms/60 mV 기준선을 표시해줘. Null current/margin 을 새로운 측정값0 으로 만들지 말고, degraded READ 곡선은 metrics metadata 로 실제 hold 시각과 연결해줘.

자료와 값이 충돌하면 모델/측정 간격/세션/원시 근거를 먼저 확인해줘. 확인되지 않는 내용은 **확인 불가**로 표시해줘. 존재하지 않는 실험·참고문헌·교수/조교 답변 시각·OK 화면·곡선을 만들지 말아줘. 결과를 좋게 보이도록 원래 수치나 판정 기준을 바꾸지 말아줘.

먼저 짧은 요구사항–절–근거/그림 대응표와 약12 쪽 배분을 제시하고, 이어서 **전체 보고서 본문까지 작성해줘**. 계획만 제시하고 멈추지 말아줘. 파일 생성이 가능하면 편집 가능한 문서와 PDF 를 제공하고 실제 페이지 수·한글·수식/표 잘림을 검토해줘. 불가능하면 Word 에 옮길 수 있는 본문/수식/그림 목록을 제공하고 PDF 를 만들었다고 주장하지 말아줘.

마지막에는 과제 필수 항목 누락·최종 수치/그림 일치·미완료 screenshot/이름·한계를 검토한 checklist 를 제공해줘. 첨부 원본과 저장 소자는 변경하지 말고 새로운 시뮬레이션도 수행하지 말아줘.
